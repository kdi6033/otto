# Otto 통신 프로토콜 v1.0 (초안)


Otto 로봇과 앱(웹)이 주고받는 메시지 규격이다.
메시지는 **JSON 한 줄**이고, 전송 방식(MQTT, BLE)이 바뀌어도 내용은 같다.
i2r.link의 기존 규칙(축약 필드, `c` 명령 코드)을 따른다.

---

## 1. 전송 방식

### 1.1 MQTT (기본)
| 항목 | 값 |
|---|---|
| 브로커 | `wss://broker.i2r.link:8084/mqtt` (웹), TLS 8883 (보드) |
| 명령 토픽 (앱 → 보드) | `i2r/{email}/in` |
| 응답 토픽 (보드 → 앱) | `i2r/{email}/out` |
| `{email}` | 사용자 이메일. **같은 사용자의 모든 보드가 같은 토픽을 공유**한다 |
| 대상 지정 | 메시지의 `m`(대상 보드 MAC). 보드는 `m`이 자기 MAC과 다를 때 무시한다 |
| QoS | 명령 0, 응답 0 |
| retain | 사용하지 않음 (오래된 이동 명령이 재실행되는 것을 막기 위해) |

### 1.2 BLE (나중에 추가, 선택)
| 항목 | 값 |
|---|---|
| 기기 이름 | `i2r-otto-XXXX` (앞 `i2r`로 검색) |
| 서비스 UUID | `4fafc201-1fb5-459e-8fcc-c5c9c331914b` (기존 i2r과 동일) |
| 명령 특성 (Write) | `beb5483e-36e1-4688-b7f5-ea07361b26a8` |
| 응답 특성 (Notify) | `beb5483e-36e1-4688-b7f5-ea07361b26a9` (신규) |
| 페이로드 | MQTT와 같은 JSON, UTF-8 |

BLE 패킷이 짧을 수 있으므로 모든 명령은 **가급적 100바이트 이하**로 유지한다.

---

## 2. 메시지 공통 규칙
- UTF-8 JSON 객체 한 개. 줄바꿈 없음.
- 필드명은 축약형을 쓴다. 웹은 `MQTTMessageMapper.ts`가 원본 이름을 축약형으로 바꿔 준다.
- 알 수 없는 필드는 무시한다. (앞으로 필드가 늘어도 이전 보드가 깨지지 않도록)
- **앱이 보내는 모든 명령에는 대상 보드 `m`(MAC)을 반드시 넣는다.** 이 문서의 예시는 짧게 보이려고 `m`을 생략했다. 실제 전송 예: `{"c":"ot","m":"D4:8C:49:50:46:F4","a":"wf","du":2}`
- 보드가 보내는 응답에도 자기 MAC을 `m`으로 넣는다. 같은 `out` 토픽을 여러 보드가 쓰기 때문이다.
- 불리언은 `1`/`0`으로 보낸다.
- **메시지 크기는 300바이트 이하**로 한다. 현재 `mosquitto.conf`에 `max_packet_size 304`가 있어 넘으면 브로커가 버린다. 한글은 글자당 3바이트다.

### 공통 필드
| 축약 | 원본 이름 | 형식 | 설명 |
|---|---|---|---|
| `c` | command | string | 명령 코드 |
| `m` | mac | string | 보드 MAC (응답에 포함) |
| `e` | email | string | 소유자 이메일 (상태 메시지에 포함) |
| `id` | requestId | int | 앱이 붙이는 요청 번호. 응답에 그대로 돌려준다. 선택 |

## 4. 동작 명령 `ot`

```json
{"c":"ot","a":"wf","du":2}
```

### 4.1 필드
| 축약 | 원본 이름 | 형식 | 필수 | 설명 |
|---|---|---|---|---|
| `c` | command | string | O | `"ot"` |
| `a` | action | string | O | 동작 코드 (4.2) |
| `du` | duration | int | X | 동작을 유지할 시간(초). 1~30, 기본 2 |
| `sp` | speed | int | X | 속도 1~100(%), 기본 100. 반복 동작에만 적용 (4.3) |
| `yr` | hipRight | int | `hip`만 | 오른쪽 엉덩이 각도 0~180 (90=가운데) |
| `yl` | hipLeft | int | `hip`만 | 왼쪽 엉덩이 각도 0~180 (90=가운데) |
| `rs` | rightSpeed | int | `feet`만 | 오른발 속도 -400~400 (양수 앞, 음수 뒤, 0 멈춤) |
| `ls` | leftSpeed | int | `feet`만 | 왼발 속도 -400~400 |

> `l`은 기존 규격에서 센서 하한값(`sensorLowValue`)이므로 발 속도에 쓰지 않고 `rs`, `ls`를 쓴다.

### 4.2 동작 코드 (`a`)
| 코드 | Otto 함수 | 설명 | 종류 |
|---|---|---|---|
| `wf` | `walkFront()` | 앞으로 걷기 | 반복 |
| `wb` | `walkBack()` | 뒤로 걷기 | 반복 |
| `wl` | `walkLeft()` | 왼쪽으로 돌며 걷기 | 반복 |
| `wr` | `walkRight()` | 오른쪽으로 돌며 걷기 | 반복 |
| `sf` | `slideFront()` | 좌우 교대로 앞으로 | 반복 |
| `sb` | `slideBack()` | 좌우 교대로 뒤로 | 반복 |
| `sl` | `slideLeft()` | 두 발로 왼쪽 돌기 | 반복 |
| `sr` | `slideRight()` | 두 발로 오른쪽 돌기 | 반복 |
| `rf` | `rollingFront()` | 앞으로 계속 굴리기 | 반복 |
| `rb` | `rollingBack()` | 뒤로 계속 굴리기 | 반복 |
| `rr` | `rollingRight()` | 제자리 오른쪽 돌기 | 반복 |
| `rl` | `rollingLeft()` | 제자리 왼쪽 돌기 | 반복 |
| `dn` | `danceRightRightTurn()` | 춤 | 반복 |
| `hip` | `moveHip(yr, yl)` | 엉덩이 각도 지정 | 자세 유지 |
| `feet` | `ottoRollFeet(rs, ls)` | 발 속도 지정 | 반복 |
| `stop` | (정지) | 모든 동작 정지 | 즉시 |

- **반복**: `du`초 동안 해당 함수를 계속 호출한다.
- **자세 유지**: 각도를 한 번 적용하고 다음 명령이 올 때까지 유지한다. `du`는 무시한다.
- **정지(`stop`)**: 발을 멈추고(`ottoRollFeet(0,0)`), 엉덩이를 중립(90)으로 돌린다. 응답은 항상 `ok:1`.

#### 예시
```json
{"c":"ot","a":"wf","du":2}
{"c":"ot","a":"rr","du":5,"id":12}
{"c":"ot","a":"hip","yr":80,"yl":100}
{"c":"ot","a":"feet","rs":80,"ls":-80,"du":3}
{"c":"ot","a":"stop"}
{"c":"ot","a":"wf","du":3,"sp":50}
```

### 4.3 속도 `sp`
- 100이 [로봇 맞추기]에서 맞춘 기본 속도이고, 50이면 절반이다.
- 발 속도(`RL_SPEED_US`, `RR_SPEED_US`)와 기울이는 속도(`TILT_STEP_DELAY`)에 같은 비율을 적용한다. 값이 낮을수록 천천히 움직인다.
- 서보는 너무 느리면 힘이 약해져 못 걷는 경우가 있으므로, 보드는 **하한 20**으로 자른다.
- `hip`, `feet`는 각도·속도를 직접 지정하므로 `sp`를 무시한다.

### 4.4 시퀀스 `oq`
여러 동작을 순서대로 실행한다. 한 메시지에 담기 위해 단계를 배열 `[동작, 초, 속도]`로 줄여 쓴다.

```json
{"c":"oq","q":[["wf",2],["rr",3,50],["dn",4],["stop"]],"rp":2,"id":7}
```
| 축약 | 원본 이름 | 형식 | 설명 |
|---|---|---|---|
| `q` | steps | array | 단계 목록. 최대 **8단계** |
| `rp` | repeat | int | 전체 반복 횟수 1~10, 기본 1 |

- 단계 `[a, du, sp]`에서 `du`는 기본 2, `sp`는 기본 100이다. `hip`, `feet`는 시퀀스에 넣을 수 없다.
- 전체 실행 시간(단계 `du` 합 × `rp`)은 **120초 이하**여야 한다. 넘으면 `bad_param`.
- 시퀀스는 단계가 끝나면 다음 단계로 자동으로 넘어간다. 앱이 계속 보낼 필요가 없다.
- 중간에 `ot` 또는 `stop`을 받으면 시퀀스를 즉시 중단한다.
- 시작할 때 `{"c":"oq","ok":1}`, 끝나면 `{"c":"oq","done":1}`을 응답한다.
- 시퀀스 저장(보드에 이름 붙여 저장)은 v1에 넣지 않는다. 앱이 저장해 두었다가 보낸다.

### 4.5 LED `ol`
WS2812B 16개(`led.ino`)를 제어한다.

```json
{"c":"ol","ef":"rb"}
{"c":"ol","ef":"sd","co":"ff0000","br":80}
{"c":"ol","ef":"off"}
```
| 축약 | 원본 이름 | 형식 | 설명 |
|---|---|---|---|
| `ef` | effect | string | 효과 코드 |
| `co` | color | string | `rrggbb` 16진수 소문자. `sd`, `bk`, `fl`에서 사용. 기본 `ffffff` |
| `br` | brightness | int | 밝기 0~255. 기본은 현재 값 유지 |

| `ef` | 효과 | 비고 |
|---|---|---|
| `off` | 끄기 | |
| `sd` | 단색 켜기 | `co` 사용 |
| `rb` | 무지개 | `rainbowEffect()` |
| `bk` | 점멸 | `co` 사용 |
| `fl` | 흐름 | `co` 사용 |

- `rb`, `bk`, `fl`은 LED 전용으로 계속 반복하고, 다음 `ol` 명령이 오기 전까지 유지한다. 이동 동작과 동시에 쓸 수 있도록 **LED도 `loop()`에서 논블로킹으로** 처리한다.
- LED는 LLM 대화 중 상태 표시(듣는 중 초록, 대기 빨강)에도 쓴다. 대화 모드(`lm:1`)에서는 보드가 LED를 자동으로 제어하고, 앱의 `ol` 명령은 `busy`로 거절한다.
- `co`가 `rrggbb`가 아니면 `bad_param`.

### 4.6 LLM 대화 `lm` `lt` `lq` `lr`
`show.ino`의 음성 대화(마이크 → STT → LLM → TTS)를 앱에서 켜고 끌 수 있게 한다.

```json
{"c":"lm","v":1}
{"c":"lt","tx":"안녕하세요"}
{"c":"lq","tx":"오늘 날씨 어때?"}
```
| 명령 | 필드 | 동작 |
|---|---|---|
| `lm` | `v`: 1 켜기 / 0 끄기 | 켜면 마이크로 말을 듣고 대답한다. 끄면 대화 중단 |
| `lt` | `tx`: 문장 (최대 80자) | LLM을 거치지 않고 문장을 그대로 음성(TTS)으로 말한다 |
| `lq` | `tx`: 질문 (최대 80자) | 텍스트 질문을 LLM에 보내고 답을 음성으로 말한다 |

**대화 기록 알림 (보드 → 앱)** — 한 턴이 끝날 때마다 발행한다.
```json
{"m":"D4:8C:49:50:46:F4","c":"lr","us":"앞으로 가","tx":"네, 앞으로 갈게요!"}
```
| 필드 | 설명 |
|---|---|
| `us` | 사용자가 한 말 (STT 결과, 최대 80자로 자름) |
| `tx` | 로봇의 답 (최대 80자로 자름) |

MQTT 크기 제한 때문에 앱 화면에 보이는 대화는 잘린 문장이다. 음성은 전체가 재생된다.

**LLM이 로봇을 움직이게 하기**
- LLM 답변에 동작 요청(예: "앞으로 가", "춤춰")이 있으면, 보드가 허용된 동작 코드로 바꿔 `oq`와 같은 방식으로 실행한다.
- 안전을 위해 LLM이 시작한 동작은 **`du` 최대 5초, `hip`/`feet` 금지**로 제한한다.
- 사용자가 `stop`이나 `lm:0`을 보내면 즉시 멈춘다.

**LLM 실행 위치 (결정 필요)**
| 방식 | 설명 | 장단점 |
|---|---|---|
| A. 보드가 직접 호출 | 지금 `show.ino`처럼 보드가 Gemini를 호출 | 구현이 쉽다. **API 키가 보드 펌웨어에 들어가** 유출 위험이 크다 |
| B. 백엔드가 중계 (권장) | 보드는 `https://i2r.link/api/llm`으로 음성/텍스트를 보내고, 키는 서버 `.env`에만 둔다 | 키가 안전하고, 사용자별 사용량 제한과 기록을 서버에서 할 수 있다. 백엔드에 API 추가 필요 |

프로토콜(위 명령·응답)은 A, B 모두 같다. B로 가면 `/api/llm`은 JWT 인증과 기기당 호출 횟수 제한을 둔다.

## 5. 보드 동작 규칙

Otto 함수는 한 번 부르면 한 동작만 하고 끝난다. 보드는 **논블로킹 상태 머신**으로 처리한다.

```
명령 수신 → currentAction, until = now + du*1000 저장
loop(): until 전이면 currentAction 함수를 계속 호출
        until이 지났거나 'stop' 수신 → ottoStop()
```

1. 새 명령이 오면 진행 중이던 동작을 즉시 정지하고 새 동작으로 바꾼다. (대기열 없음)
2. `loop()`는 MQTT 수신을 막으면 안 된다. `delay()`를 길게 쓰지 않는다.
3. `du`는 1~30으로 자르고 30을 넘기지 않는다.
4. 같은 동작의 명령이 반복해서 오면(버튼 누르고 있는 경우) 동작을 다시 시작하지 않고 `until`만 연장한다.
5. MQTT 연결이 끊기면 진행 중인 동작을 즉시 멈춘다.
6. 부팅 직후에는 정지 상태에서 시작한다. 전원이 켜지자마자 움직이면 안 된다.

### 앱의 사용 방법 (누르고 있는 동안 이동)
| 앱 | 보내는 메시지 |
|---|---|
| 버튼을 누름 | `{"c":"ot","a":"wf","du":2}` |
| 누르고 있는 동안 | 0.8초마다 같은 메시지 반복 |
| 버튼을 뗌 | `{"c":"ot","a":"stop"}` |
| 통신이 끊김 | `du`가 지나면 보드가 스스로 멈춤 |

## 6. 응답 (보드 → 앱)

### 6.1 명령 응답
```json
{"m":"D4:8C:49:50:46:F4","c":"ot","a":"wf","ok":1,"id":12}
```
| 필드 | 설명 |
|---|---|
| `ok` | 1 성공, 0 실패 |
| `err` | 실패 이유 (아래 6.2). `ok:0`일 때만 |
| `id` | 요청의 `id`를 그대로 반환 (있을 때만) |

반복 명령을 0.8초마다 보내면 응답도 계속 오므로, 보드는 **동작이 바뀔 때만** 응답한다. (같은 동작 연장은 응답 생략)

### 6.2 오류 코드
| `err` | 의미 |
|---|---|
| `bad_json` | JSON 해석 실패 |
| `bad_action` | 알 수 없는 `a` 값 |
| `bad_param` | 필수 필드 누락 또는 범위 초과 |
| `busy` | 펌웨어 업데이트 중 등 동작할 수 없는 상태 |

### 6.3 상태 (`gs`)
앱이 `{"c":"gs"}`를 보내면 보드가 현재 상태를 응답한다.
```json
{"m":"D4:8C:49:50:46:F4","e":"user@email.com","c":"gs","t":5,"ver":"1.0","act":"wf","voltBat":3.9}
```
| 필드 | 설명 |
|---|---|
| `t` | 보드 종류 번호. 기존 규격(`3`=i2r-03)에 따라 Otto 보드(i2r-05)는 `5` (README 표에 등록 필요) |
| `ver` | 펌웨어 버전 |
| `act` | 현재 동작 코드. 정지면 `"stop"` |
| `voltBat` | 배터리 전압 (측정 회로가 있을 때) |

백엔드는 `gs`를 받으면 MongoDB 기기 정보를 갱신하므로, Otto도 기존 기기 목록에 그대로 나타난다.

### 7.1 MQTTMessageMapper.ts 추가

| `rightSpeed` | `rs` | 필드 |
| `leftSpeed` | `ls` | 필드 |
| `requestId` | `id` | 필드 |
| `speed` | `sp` | 필드 |
| `steps` | `q` | 필드 (시퀀스 배열) |
| `repeat` | `rp` | 필드 |

> `f`(fileName), `t`(type), `l`(sensorLowValue)와 겹치지 않도록 `ef`, `tx`를 썼다. `q` 배열은 `compressMessage`가 중첩 객체를 처리하지 않으므로 **그대로 통과**시키도록 매퍼에 예외를 추가해야 한다.

### 7.2 전송 추상화
```ts
interface OttoTransport {
  send(msg: object): Promise<void>;     // 원본 이름 JSON
  onMessage(cb: (msg: object) => void): void;
}
// MqttTransport : MQTTService.publish('i2r/'+mac, JSON.stringify(msg))
// BleTransport  : 명령 특성에 write, 응답 특성 notify 구독 (나중)
```
화면은 `OttoTransport`만 사용한다.

## 8. 보안 주의
- `i2r/{email}/in`에 발행할 수 있으면 그 사용자의 로봇을 움직일 수 있다. 현재 브로커는 익명 접속을 허용하므로, 배포 전에 **계정별 토픽 권한(ACL)** 을 설정해야 한다.
- 위험을 줄이는 최소 조치: 보드는 `e`(이메일)가 소유자와 같은 명령만 처리하는 방법을 검토한다.
- 보드 소스에 Wi-Fi 비밀번호나 API 키를 넣지 않는다. (`show.ino`에 노출된 키는 폐기하고 새로 발급)

## 9. 버전 관리
- 이 문서는 v1.0 초안이다. 필드를 추가할 때는 기존 필드의 의미를 바꾸지 않는다.
